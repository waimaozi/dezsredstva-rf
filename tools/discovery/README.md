# Проверка поисковой видимости

`measure.py` выполняет только чтение: Метрика (визиты, органические поисковые системы, входные страницы, возвращающиеся посетители, скачивания и сигналы читателей), при наличии ключа — проверка `site:` через Yandex Search API. По умолчанию берёт семь завершённых суток по московскому времени. Расписания не создаёт.

```sh
python3 tools/discovery/measure.py \
  --oauth-file ~/.config/chemitech/ya_direct.token \
  --ssh russian-vps \
  --search-key-file /root/chemitech-enrichment-pilot-20261006/yandex-search.key \
  --out /tmp/dezsredstva-discovery.json
```

Для сравнения периодов задайте `--start YYYY-MM-DD --end YYYY-MM-DD`. `--webmaster` дополнительно проверяет доступ к Вебмастеру и сводку целевого сайта. OAuth передаётся в удалённый процесс через stdin; ключ Search API остаётся на сервере. Ответы не содержат токенов. Ошибки API сохраняются как неизвестный результат, а не как нулевые показатели.

## Как оценивать результат

1. В Вебмастере проверить дату обхода, страницы в поиске, причины исключения и нарушения. Подтверждённое число страниц в индексе брать оттуда, не из `site:`.
2. Сопоставить показы и клики по 13 переводам в отчёте поисковых запросов Вебмастера. Отсутствие доступа к этому отчёту означает пробел в данных.
3. В Метрике сравнить визиты из Яндекса и достижение цели скачивания. Разрез `landing_pages` относит цель к входной странице визита; это не число скачиваний конкретной статьи. Событие скачивания дополнительно передаёт `article`, `asset` и `format`.
4. Сравнивать полные периоды после подтверждённого повторного обхода. Принятие IndexNow не подтверждает индексирование; рост трафика после изменения сам по себе не доказывает его причину.

## Сигналы читателей с 19 октября 2026

На 13 переводах и странице подборки добавлены три добровольных ответа: полезно,
не по теме, нужны подробности. Область работы необязательна; это самоописание,
а не подтверждённая профессиональная принадлежность. Имена и контакты не собираются.
Ответы передаются через существующую Метрику; блокировщики аналитики ограничивают охват.
Одно голосование на страницу за сессию вкладки обеспечивается sessionStorage;
если хранилище недоступно, повтор предотвращается только до перезагрузки страницы.

`translation_engaged_90s` означает минимум 90 секунд при видимой и активной вкладке,
с текстом в видимой области и достижением хотя бы 50% текста. Это косвенный признак
внимания, не доказательство прочтения или полезности. Для короткой страницы достаточно,
чтобы половина текста была видна. Время опроса ограничено двумя секундами на шаг,
чтобы долгий сон браузера не превращался в чтение. Подборка учитывается отдельно
в параметре `content_kind`, хотя техническое имя цели общее.

`reader-goals.json` содержит проверенные ID целей и дату начала измерения.
`reader_measurement.coverage` принимает `not_measured`, `partial_period` или `measured`;
день запуска считается неполным. Нули API до запуска не означают отсутствие читателей.
Если выпуск задержан хостингом, серверный конфиг содержит `deployment_pending: true`:
покрытие обозначается `awaiting_deployment`, без наблюдаемого периода. Одноразовая
проверка снимает флаг только после подтверждения живых страниц, фиксирует время
проверки в `verified_live_at` и устанавливает дату начала по Москве. Конфиг и это
состояние нужно сохранять при следующих обновлениях серверного мониторинга.
`reader_goals` возвращает достижения в порядке `goal_metric_order`.
`returning_visitors` разделяет визиты по признаку нового пользователя Метрики.
`reader_responses` читает параметры события: цель → схема → тип материала → путь
страницы → область работы → ответ. Это сохраняет связь ответа с конкретной страницей,
даже если читатель открыл несколько статей за визит. Число пользователей нельзя
суммировать между строками; соседние ежедневные отчёты перекрываются по датам.

Все шесть отчётов Метрики входят в проверку работоспособности мониторинга.
Ошибки API остаются неизвестными данными. При обновлении мониторинга необходимо
устанавливать `reader-goals.json` рядом с `measure.py` и `snapshot.py`.
Проверки браузера используют заглушку Метрики, без отправки тестовых голосов.

## Ежедневное наблюдение

С 17 октября 2026 года `dezsredstva-discovery.timer` на `russian-vps` запускает
`snapshot.py` ежедневно в 09:20 по Москве (плюс до двух минут разброса).
Первый реальный запуск завершился успешно. Каждая запись охватывает семь
завершённых суток, поэтому соседние записи перекрываются: складывать их нельзя.

Код установлен в `/opt/dezsredstva-discovery`, история и агрегированные данные
Метрики хранятся приватно в `/var/lib/dezsredstva-discovery`. `latest.json` —
последний полученный ответ, `health.json` — результат последней попытки,
`last-success.json` — дата последнего полного успешного чтения. Ошибки транспорта
не заменяют прежние данные нулями. При ошибке служба завершается с ненулевым
кодом и делает до трёх попыток за два часа; журнал доступен через
`journalctl -u dezsredstva-discovery.service`.

```sh
ssh russian-vps 'systemctl list-timers dezsredstva-discovery.timer --no-pager'
ssh russian-vps 'cat /var/lib/dezsredstva-discovery/health.json'
```

Ключ Search API остаётся на российском сервере. OAuth Метрики хранится отдельно
с правами 600 и поступает в процесс через stdin. Служба только читает данные;
она не отправляет письма, не меняет статьи и не считает ответ `site:` числом
страниц в индексе. Код 15 Search API означает отсутствие найденных документов;
другие коды ошибок делают результат неполным. Остановка: `systemctl disable
--now dezsredstva-discovery.timer`.
